# Architecture inspection and implementation

## Discovered before changes

The parent repository contains six Git submodules. `ocudu/docker/open5gs-split/docker-compose.yml` is the working split-core deployment: MongoDB and eleven Open5GS NFs, with named `open5gs_*` containers, `open5gs-split-5gc` (172.20.1.0/24), and `ocudu_ran` (10.53.1.0/24). AMF is reachable at 10.53.1.2:38412/SCTP. gNB and OAI UE are host binaries using ZMQ ports 4556/4557. No radio/core source changes are needed for Inspector.

`kafka-setup/docker-compose.kafka.yml` runs Apache Kafka 3.7 KRaft and Kafka UI. Internal clients use `kafka:9092`, host clients `localhost:9094`. The existing named broker volume is `5gi-kafka-data`. The external core network must exist first. The log-agent's own Compose file is a stale copy of the core deployment with inappropriate relative and host-specific mounts; it is not the orchestrator used here.

`rca-log-agent` discovers Docker containers whose names contain `open5gs`, follows their stdout/stderr through Docker's API, wraps lines with container provenance, Docker timestamp and producer sequence, and publishes `5g.raw.<nf>`. SQLite watermarks advance after acknowledgement. The current envelope lacks the optional schema/version fields; the ingester explicitly supports this legacy contract. The agent also discovers MongoDB, although the ingester's default NF topic list excludes it. Logs rotate across three partitions, so Kafka ingestion order is not signalling order.

`rca-ingester` is a Python CLI with kafka-python and a standard-library parser/sealer/JSONL store. It parses nested AMF events, legacy text, and SBI records; builds the A1 identity graph, A3 incident chains and telemetry; and signs replay output. Before this work, its consumer exited after an idle timeout and its derived outputs were finalized only at end-of-stream. There was no HTTP API.

The nested `demo-ui` was independent React/Vite with lucide icons. It fetched a static `demo-data.json` generated by replaying fixtures, not the running pipeline. That is why the web application belongs at the parent repository's `frontend/`.

## Resulting data path

```text
Open5GS NF containers
  → existing RCA log-agent (Docker log envelopes)
  → existing Kafka, 5g.raw.{amf,smf,nrf,udm,ausf,pcf,udr,bsf,scp,nssf,upf}
  → existing parser / sealing / durable JSONL pipeline
  → s5.observability (UE/procedure/incident projection)
  → s5.api (localhost:8000)
  → frontend/ (localhost:5173, HTTP polling every 3 seconds)
```

The API process owns a continuous Kafka consumer and a separate projection worker. The projection reads only complete sealed JSONL records, removes duplicate Kafka coordinates, and refreshes every two seconds. It is rebuilt from durable evidence on restart. Raw Docker logs and fixtures cannot feed the frontend directly. The existing replay and batch correlation commands remain available; live incident observations reuse the existing root-cause classifier and expose its result explicitly as a rule classification.

Identity linking uses explicit co-occurrence of SUPI/IMSI, SUCI, GUTI and scoped local UE IDs. It does not merge on a shared gNB, PDU session number or nearby timestamp. Conflicting temporary-ID ownership remains unresolved. SUCI/GUTI link across NFs; AMF/RAN IDs are container-scoped. IMSI fragments in debug hex dumps are excluded. This conservative implementation can leave temporary contexts unresolved after ID reuse; it does not claim complete lifecycle inference.

Timeline ordering uses event timestamps, source container and producer sequence with HLC as a final tie breaker. Registration requests create attempts; completion, rejection and deregistration update the UE state. Registration acceptance alone remains `accepted`, and PDU context creation alone is not an active internet session. Missing completion produces an incomplete observation when a new attempt arrives, not a fabricated timeout. Three attempts in 60 seconds produce a repeated-attempt incident. Generic missing-stage/suspicious-sequence diagnoses without explicit evidence are not invented.

## Scope and limitations

- This is a local operator MVP, bound to loopback. Vite proxies `/api` to the backend. It is not a public multi-user/authenticated deployment.
- The API retains the up to 45,000 UE-associated/failure records plus 5,000 recent raw records in memory and returns the latest 500 normalized records in the dashboard snapshot. Counts apply to that retained evidence. This prevents idle NF heartbeat traffic from immediately evicting the UE journey. The individual collection endpoints paginate, with a maximum page size of 1,000. Durable JSONL is not automatically deleted.
- The live snapshot includes complete retained UE timelines, so a larger deployment needs database-backed pagination and incremental projection indexes. The original ingester also retains its batch correlation context in memory.
- Health shows API/consumer state, Kafka TCP reachability, last successful poll and last durable ingestion. Core/agent are deliberately marked “not directly probed”; their running state is verified separately with Docker. A reachable Kafka socket does not prove zero lag or healthy NFs.
- Raw debug bodies can contain sensitive protocol material in existing historical stores. The web API exposes normalized evidence and provenance, not those bodies. New parser handling omits binary debug payloads.
- Existing historical JSONL is not rewritten when parser rules change. Failed historical parses remain in `parse_errors.jsonl`. For a complete reparse, use a **new output directory and consumer group together**, preserving the old evidence.
- A rule classification is not proof of an underlying root cause. Explicit NF cause/reason is shown separately; unknown causes remain unknown. Incidents are failure observations, not a deduplicated ticket lifecycle.
- Commits/checkpoints preserve the existing at-least-once semantics. The live projection deduplicates Kafka topic/partition/offset. Crash-proof atomic coordination of Kafka and the local file store is outside this MVP.

## API

- `GET /api/health`
- `GET /api/overview`
- `GET /api/snapshot` — the UI's single consistent polling payload
- `GET /api/ues?offset=0&limit=100`
- `GET /api/ues/{url-encoded-id}`
- `GET /api/ues/{url-encoded-id}/timeline`
- `GET /api/procedures?offset=0&limit=100`
- `GET /api/incidents?offset=0&limit=100`
- `GET /api/events?offset=0&limit=100`

The old fixture data generator and output are preserved under `rca-ingester/docs/scripts` and `docs/public`, outside the production frontend. The reusable metric component, React/Vite dependencies, and icon approach were retained in the new application.
